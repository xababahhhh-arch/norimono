# さくらプラザ イベント広報生成システム

戸塚区民文化センターさくらプラザの公演・イベントについて、**チラシ（PDF / JPG / PNG）から情報を構造化し、担当者が確認したうえで**、HPイベントページ・SNS投稿・画像代替テキスト・アクセシビリティチェックを **同じ `event.json` から** 生成するための静的Webアプリです。

> 目標：担当者の経験やHTML知識に依存せず、チラシさえあれば、誰でも同じ基準・同じ品質・同じアクセシビリティ水準でHPとSNS広報を作成できること。
> ただし **完全自動公開はしません**。「自動抽出 → 人間が確認 → 生成」（Human-in-the-loop）を必須とします。

## このシステムがしないこと

- チラシから直接HPやSNSの文章を作ることはしません（必ず `event.json` を経由します）。
- チラシに書かれていない出演者経歴・受賞歴・曲目・日時・料金・発売情報・評価などを「事実」として書き足すことはしません。足りない情報は「情報なし」「要確認」「追加情報が必要」と表示します。
- 「必見」「絶対に見逃せない」「世界最高」など、資料で裏付けられない主観的な表現を自動で書くことはしません。
- 「WCAG AAA 適合」と断定しません。表示するのは **「AAA対応チェック」** の結果です。
- アップロードしたファイルを外部サーバーへ送りません（Phase 1 はすべてブラウザ内で処理します）。

## 使い方（5ステップ）

| STEP | 画面 | 担当者がすること |
|---|---|---|
| 1 | チラシをアップロード | PDF / JPG / PNG を選ぶ（表面・裏面の複数可）。文字が取れないときはチラシの文字を貼り付けることもできます |
| 2 | 自動解析 | ボタンを押すだけ。日付・時刻・料金・電話番号などの候補を取り出し、どのページのどの文字から取ったかを記録します |
| 3 | 内容を確認・修正 | 左にチラシ、右に取り出した情報。一つずつ「確認済み」にします。必須項目がすべて確認済みになるまで確定できません |
| 4 | HP/SNS生成 | HP用HTML、プレーンテキスト、X・Facebook・Instagram（各3種類）、代替テキスト、アクセシビリティ報告を作ります |
| 5 | コピーまたは書き出し | 各出力のコピーボタン、またはファイル保存 |

画面の上部には、いまどのSTEPにいるかが常に表示されます。

## 起動方法

ビルドは不要です。

- **GitHub Pages**：リポジトリの Pages を有効にすると `https://<user>.github.io/<repo>/sakura-event/` で開けます。
- **手元で試す**：ES Modules を使うため、`file://` ではなく簡易サーバーで開いてください。

```sh
cd sakura-event
npx http-server -p 8080   # もしくは python3 -m http.server 8080
# → http://localhost:8080/
```

## テスト

```sh
cd sakura-event
npm install     # テスト用の linkedom だけを入れます（アプリ本体は依存なし）
npm test
```

`fixtures/` に 11 種類のイベント形式（通常クラシック、複数出演、0歳から、ワークショップ、複数回、無料、参加者募集、オープンデー、完売、受付終了、出演者変更）の `event.json` と、抽出テスト用のチラシ文字データがあります。

## チラシの文字を貼り付ける運用（Phase 1 の標準の使い方）

実物のチラシ（Illustrator で文字をアウトライン化したPDF）からは文字を取り出せないことが確認されました（`REAL_DATA_TEST_UNPLUGGED.md`）。文字原稿がある場合は、**チラシの文字原稿（入稿データのテキスト、Word等）を STEP 1 の「チラシの文字を貼り付け」欄に貼り付ける**のが最も正確です。原稿がない場合は、次の「ブラウザ内OCR」を使います。

1. PDFも一緒に選ぶと、STEP 3 の左側にチラシの画像が表示され、照合しやすくなります。
2. 解析後、STEP 3 の一番上に **「判断が必要な記載」** が原文つきで表示されます（開場・開演を区別できない行、車椅子に関する判断できない文、別企画と思われる料金など）。原文を見て必要な項目に入力し、「対応済みにする」を押します。
3. 各項目には **出典（原文）・抽出根拠・確認が必要な理由** が表示されます。確信度の数値は表示しません。
4. **販売・受付状況はチラシからは決めません。** 窓口・販売システムで確認して設定してください（「未確認」のままでは確定版を生成できません。開催日・発売日から自動で「発売中」にはしません）。
5. 「確認済みの内容で生成する」を押しても**公開はされません**。上長の承認後、担当者が CMS・各SNS で公開し、STEP 5 に承認・公開の記録を残します。

## 端末で動かす（公開せずに使う）

このアプリは、**index.html をダブルクリックして開くと動きません**（ブラウザの安全の仕組みで、プログラムの読み込みが止められるため）。この場合は、画面の上に「アプリを起動できませんでした」と原因を表示します。次の手順で、この端末の中だけで動かしてください（外部へは何も送りません）。

1. GitHub のこのブランチから「Code」→「Download ZIP」でダウンロードし、展開します（`sakura-event` フォルダ一式を使います）。
2. `sakura-event` フォルダの起動用ファイルを実行します。
   - Windows：`start-local.bat` をダブルクリック（Python が必要です。入っていない場合は情報システム担当に相談してください）
   - Mac：`start-local.command` を右クリック →「開く」
3. ブラウザで `http://localhost:8000/` が開きます。開かない場合は、そのアドレスを入力してください。
4. 使い終わったら、起動用ファイルの画面を閉じます。

- `http://localhost` 以外（社内サーバーの http など）で開いても動きますが、ファイルの同一性の確認（SHA-256）はブラウザ内の自前の計算になり、大きなファイルでは少し時間がかかります。
- 最新の Chrome・Edge・Firefox・Safari で動作します（PDF.js と OCR は Worker・WebAssembly を使います）。
- 以前に共有した Claude の Artifact「さくらプラザ 広報原稿ジェネレーター（テスト版）」は、このアプリとは**別の実装**です（文字の入ったPDFだけに対応し、OCRはありません。外部CDNからライブラリを読み込み、AIの文章生成を使います）。アウトライン化したチラシPDFは読めません。

## ブラウザ内OCR（最終チラシPDF・画像を読む）

1. STEP 1 で PDF・JPG・PNG を選びます。PDFはページごとに文字の有無を調べ、**文字のないページ（アウトライン化）だけ OCR の対象**にします。
2. STEP 2 で「文字を取り出す」を押すと、ページを順に画像化して OCR します（進捗表示、キャンセル、ページごとの再実行）。ページごとに「PDFの文字／OCR／PDFの文字＋OCRにしかない行」を選べます（無条件に連結しません）。
3. 解像度（200／300〔標準〕／400 dpi）と白黒化の明るさを「OCRの設定」で変えられます。実物チラシで 300dpi・2ページ 約28秒、メモリ最大 約0.8GB（`REAL_DATA_TEST_UNPLUGGED.md` 12章）。
4. STEP 3 では各項目に **取得方法（PDFの文字から取得／OCRで取得／担当者が修正）** が表示され、項目を選ぶとチラシ上の読み取り位置が枠で表示されます。**OCRの信頼度で確認済みにはしません。** 疑わしい文字（読めない曜日、「2.500円」のような金額 等）は推測で直さず「要確認」にします。
5. OCR の資材（Tesseract.js、Worker、WASM、日本語・英語の学習データ）は `vendor/tesseract/` に同梱し、外部CDNに接続しません。**PDF・ページ画像・OCR結果・修正内容はどこにも送信しません。** 資材を読み込んだ後はネットワークを切っても動きます。
6. 読み込んだファイルは **ファイル名・SHA-256・取込日時** を記録します。同じファイルを再度選んでも新しい版にはしません。ハッシュは同一性の確認だけに使い、「最新版」「承認済み」とは判定しません（担当者が「版を確認した」を押します）。

## Phase 1 でできること

- **入力**：PDF（文字の入ったもの・アウトライン化したもの）、JPG・PNG（ブラウザ内OCR）、チラシの文字の貼り付け、保存した event.json の読み込み
- **自動解析（ブラウザ内・ルールベース）**：日付（全角・和暦・年省略・丸付き曜日）、曜日、開場・開演・終演、複数回公演、会期、料金・席種・税込、年齢・膝上鑑賞、出演者（楽器・役割・読み・ローマ字）、プロフィール、曲目、発売日・先行、チケット取扱・Pコード/Lコード、対象・定員・持ち物・申込期間・抽選、主催・共催・後援・協賛・助成・協力、問い合わせ（電話・メール）、URL、バリアフリー情報、注意事項、複合イベントの小イベント、イベント種別の推定
- **確認画面**：左にチラシ、右に項目。各項目に出典（ファイル・ページ・元の文字）と確信度、状態（✓確認済み／！要確認／－情報なし）。曜日の照合、形式チェック、修正の提案。販売・受付状況と更新履歴の編集
- **確定ゲート**：タイトル・サブタイトル・開催日・曜日・開場・開演・会場・出演者・楽器/役割・**プロフィール**・曲目・料金・年齢制限・発売情報・チケット取扱・主催・問い合わせ・電話番号・外部URL・入力資料の版・販売状況・判断が必要な記載、および**そのほか値のある掲載項目すべて**が確認済みでないと「確定して生成」できない。未確認の値はHP・SNSの確定版に出ない（下書きは生成可、［要確認］と下書き表示つき。SNSの下書きにも未確認のプロフィールは使わない）
- **プロフィール**：掲載する場合は原文と照合して「確認済み」にする。照合できない場合は「プロフィールの掲載」で「掲載しない」を選ぶ（HP・SNSに出さない。event.json には原文を残す）
- **取り落とし防止**：料金の行・料金欄で料金として取り出せなかった金額（「円」が読めない等）、同じ発売の記載の食い違い、開催日より後の発売日、「：」を含む出演者名は「判断が必要な記載」になり、対応するまで確定できない
- **出力**：event.json、HP用HTML（CMS貼り付け用／確認用の完全なページ）、HP用プレーンテキスト、X・Facebook・Instagram 各3種類、代替テキスト、AAA対応チェック報告。すべてにコピーボタンと保存ボタン
- **作業の保存**：**ブラウザの保存領域には自動保存しません。** 「event.json を保存」ボタンで端末へ保存し、次回は event.json を読み込んで再開します。「すべてクリア」で画像・Worker・参照を解放します。以前の版が残した保存データがあれば、消去ボタンを表示します

## ファイル構成

```
sakura-event/
├── index.html / css/app.css / js/app.js   画面（5ステップ）
├── js/core/      スキーマ・日付・確認状態・検証・種別推定・禁止表現
├── js/extract/   PDF.js による文字抽出・画像化、ブラウザ内OCR、ページ文字の組み合わせ、ルールベース抽出
├── js/generate/  HP・テキスト・SNS・代替テキスト
├── js/a11y/      AAA対応チェック
├── js/ai/        文章生成 adapter（外部AIは未実装・送信同意の仕組みのみ）
├── js/ui/        確認フォーム・プレビュー・出力パネル
├── vendor/pdfjs/ PDF.js 4.10.38（Apache-2.0、同梱）
├── vendor/tesseract/ Tesseract.js 7.0.0・core 7.0.0（Apache-2.0）、jpn/eng 学習データ（同梱）
├── fixtures/     テスト用の架空イベント（events/*.json、raw/*.txt）
└── tests/        node:test
```
