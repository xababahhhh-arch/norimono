# ARCHITECTURE

## 1. 過去3年度のイベントページから想定するパターン

> 注意：開発環境から `totsuka.hall-info.jp` へ接続できなかったため、以下は依頼時に示されたイベント形式の一覧と、公共ホールのイベントページで一般的な構成から整理したものです。実ページとの差異は「9. 要検証事項」で確認します。

## 2. イベント分類

| event_type | 日本語 | 主な判定語（ルールベース） | 主に表示する項目 |
|---|---|---|---|
| `performance` | 公演 | 開演、開場、全席指定、リサイタル、コンサート、ライブ、公演 | 出演・プログラム・開場/開演・料金・チケット |
| `family_performance` | ファミリー公演 | 0歳、親子、ファミリー、膝上、こども、キッズ | 上記＋対象年齢・膝上・ベビーカー等 |
| `workshop` | ワークショップ | ワークショップ、体験、つくろう、参加者、持ち物 | 対象・定員・参加費・持ち物・申込 |
| `lecture` | 講座 | 講座、講演、レクチャー、セミナー、講師、受講 | 講師・回数・受講料・申込 |
| `exhibition` | 展示 | 展示、展覧会、ギャラリー、会期、入場無料 | 会期・開館時間・休館日 |
| `recruitment` | 参加者募集 | 募集、応募、オーディション、出演者募集、団員 | 応募資格・応募期間・選考・通知 |
| `multi_event` | 複合イベント | オープンデー、フェスティバル、同時開催、プログラム一覧、各回 | 小イベント一覧（sub_events） |

- 判定はキーワードの重み付き加点で行い、最高点のタイプを **候補** として提示します。確信度（confidence）も表示します。
- **担当者はいつでも種別を変更できます。** 種別を変えると表示する項目（HP・確認画面）が切り替わります。値は消しません。
- 「共催」は種別ではなく `organization.co_organizer` の有無で表現します（どの種別でも共催はありうるため）。
- ジャズ等のジャンルは `genre` で保持します（種別は `performance`）。

## 3. データフロー

```
┌───────────────┐
│ チラシ         │ PDF / JPG / PNG（表・裏）、または貼り付けた文字
└──────┬────────┘
       │ STEP 1-2（ブラウザ内のみ）
       ▼
┌───────────────┐  PDF.js：ページごとの文字と文字サイズ
│ raw extraction │  文字のないページ・画像：PDF.js で画像化 → 白黒化 → Tesseract.js（ブラウザ内OCR、jpn+eng）
│                │  ページごとに PDFの文字／OCR／PDF＋OCRにしかない行 を選ぶ（無条件に連結しない）
│ raw.json       │  → { file, page, text, lines[] } のまま保存（加工しない）
└──────┬────────┘
       │ ルールベース抽出（extract/rules.js）
       │  各値に source_file / source_page / source_text / source_method / source_bbox を付ける
       ▼
┌───────────────┐
│ event.json     │  ← Single Source of Truth
│ (draft)        │  各項目の review = needs_review / missing
└──────┬────────┘
       │ STEP 3：人による確認・修正（確認済みにする）
       │  ・曜日をプログラムで再計算して照合
       │  ・低confidenceは自動で「要確認」
       │  ・必須項目がすべて確認済みになるまで「確定」不可
       ▼
┌───────────────┐
│ event.json     │
│ (confirmed)    │
└──────┬────────┘
       │ STEP 4：生成（generate/*.js は event.json だけを入力にする純粋関数）
       ├──────────► HP用HTML / HP用プレーンテキスト
       ├──────────► X / Facebook / Instagram（A:お知らせ B:アーティスト C:プログラム）
       ├──────────► 画像代替テキスト
       └──────────► AAA対応チェック報告（自動検査＋人の確認項目）
                     STEP 5：コピー／書き出し
```

### 原則

1. **生成器は `event.json` 以外を読まない。** チラシの生データ（raw）を生成器に渡さない。これにより HP と SNS の内容が必ず一致します。
2. **raw extraction は加工しない。** 出典（どのファイルの何ページのどの文字）を残すため、正規化前の文字列を `source_text` に保持します。
3. **状態（販売・受付）は本文と別。** 完売・受付終了・中止などは `status` と `updates[]` だけを更新し、本文は触りません。HPの状態表示と更新履歴は `status` から生成します。

## 4. ハルシネーション防止

| 対策 | 実装箇所 |
|---|---|
| 生成器は event.json の値を「組み立てる」だけで、新しい事実を作らない（テンプレート＋抽出文） | `generate/*.js` |
| 値のない項目は「情報なし」または非表示。推測で埋めない | `generate/hp.js` |
| 各値に出典（ファイル・ページ・元の文字列）と confidence を付与 | `extract/rules.js` |
| 抽出した値はすべて「要確認」。確信度の数値は表示せず、抽出根拠（`basis`）と確認が必要な理由（`reasons`）を表示 | `core/field.js`、`ui/form.js` |
| 判断できない記載（開場・開演の対応、車椅子の文の種類など）は値にせず、原文つきの「判断が必要な記載」（`meta.review_items`）にする。対応するまで確定不可 | `extract/rules.js`、`core/validate.js` |
| 販売・受付状況はチラシから決めない（初期値「未設定」、未設定では確定不可） | `core/schema.js`、`core/validate.js` |
| 生成完了・上長承認・公開を別の状態として記録（システムは公開しない） | `app.js`、`meta.workflow` |
| 年の省略された日付は年を推定するが confidence を下げ、推定したことを記録 | `extract/rules.js` |
| 曜日は日付から再計算し、チラシの曜日表記と照合。不一致は「エラー：曜日が一致しません」 | `core/validate.js` |
| 必須項目（タイトル・開催日・曜日・開場・開演・会場・出演者・料金・年齢制限・発売情報・電話番号・外部URL）が確認済みでないと確定不可 | `core/validate.js` |
| SNSの「アーティストの魅力」はプロフィール文からの抜粋のみ。プロフィールがなければ「出演者プロフィール情報を追加してください」 | `generate/sns.js` |
| 「プログラム内容について」はプログラムがなければ「プログラム情報が登録されていません」 | `generate/sns.js` |
| 禁止表現（必見、世界最高 など）を出力から検出し、資料に同じ語がない場合は警告 | `core/phrases.js` |
| キャッチコピーはチラシにある文言のみ（自動作成しない） | `generate/*.js` |
| 外部AIを使う場合も出力は「下書き」扱いで、同じ確認ゲートを通す | `ai/adapter.js`（Phase 3） |

## 5. UI構成

```
┌──────────────────────────────────────────────────────────┐
│ [スキップリンク]  さくらプラザ イベント広報生成                │
│ ① アップロード ─ ② 自動解析 ─ ③ 確認・修正 ─ ④ 生成 ─ ⑤ 書き出し │ ← 常時表示（現在地は aria-current="step" と「現在」の文字）
├──────────────────────────────────────────────────────────┤
│ STEP 3 の例                                                │
│ ┌───────────────┐ ┌─────────────────────────────┐        │
│ │ チラシプレビュー │ │ 確認の進み具合：必須 8 / 12 確認済み │        │
│ │ （ページ切替）   │ │ ▼ 基本情報                      │        │
│ │               │ │  タイトル [______] ［要確認］      │        │
│ │               │ │   出典：flyer.pdf 1ページ「…」     │        │
│ │               │ │   [確認済みにする]                │        │
│ │               │ │ ▼ 日時                         │        │
│ │               │ │  エラー：曜日が一致しません …      │        │
│ └───────────────┘ └─────────────────────────────┘        │
└──────────────────────────────────────────────────────────┘
```

- 状態は **記号＋文字＋色** で表示します（✓確認済み／！要確認／－情報なし）。色だけに頼りません。
- 各項目の横に出典（ファイル名・ページ・元の文字列）と確信度を表示します。
- 1行の入力欄、複数行の入力欄、選択肢、繰り返し項目（出演者・曲目・日程・料金・チケット取扱・小イベント）はスキーマ定義から自動で作ります（`ui/form.js`）。
- 原稿・抽出結果はブラウザの保存領域（localStorage・IndexedDB 等）に自動保存しません。event.json は「保存」ボタンで端末へ書き出し、読み込みで再開します。
- 項目を選ぶと、左のプレビューで取得元のページに移り、位置情報（OCR・PDFの文字の bbox）があれば枠で強調します。
- 幅の狭い画面では1カラムに切り替わり、チラシプレビューは上に表示します。

- `core/`, `extract/rules.js`, `generate/`, `a11y/` は DOM に依存しない純粋関数にし、Node.js でテストできるようにします（a11y チェックは Document を引数で受け取ります）。
- 外部ライブラリは PDF.js と Tesseract.js のみ（リポジトリに同梱）。テストでは linkedom を使います。

### AI adapter

```js
// ai/adapter.js
{
  id: 'local',            // 'local' | 'claude' | 'openai' ...
  label: 'ブラウザ内（外部送信なし）',
  external: false,        // true のアダプタは使用前に必ず送信同意を取る
  async extract(raw)       // → event.json 下書き（出典つき）
  async draftSns(event, platform, kind) // → 下書き文字列（Phase 1 は生成器そのもの）
}
```

外部AIを使うアダプタは、呼び出し前に次の確認を必ず表示します（キャンセル可能、既定はキャンセル）。

> このファイル・情報を外部AIサービスへ送信します。
> 送信先：（サービス名）／送信する内容：（ファイル名・項目）
> 送信してよろしいですか？

外部AIの出力も event.json の「下書き」として扱い、同じ確認ゲートを通します。

## 7. セキュリティ・プライバシー

- ファイルは `FileReader` / `URL.createObjectURL` でブラウザ内でのみ扱い、ネットワークへ送信しません。
- PDF.js・Tesseract.js（Worker・WASM・学習データを含む）は `vendor/` に同梱し、実行時に外部CDNを読みません。学習データもブラウザに保存しません（`cacheMethod: 'none'`）。
- PDF・ページ画像・OCR結果・修正内容は、サーバー・外部AI・アクセス解析・エラー収集・URLのいずれにも含めません。
- 「すべてクリア」やページを閉じたときに、PDF文書・画像のURL・OCRのWorkerを解放します。
- 生成するHTMLの値はすべてエスケープします（`<script>` 等を埋め込めない）。URLは `http:` / `https:` / `tel:` / `mailto:` のみ許可します。
- 自動保存はしません。以前の版が localStorage に残したデータがあれば、画面に知らせて消去ボタンを出します。

## 8. テスト方針

| 区分 | 内容 |
|---|---|
| 抽出 | チラシ文字データ（fixtures/raw/*.txt）から日付・曜日・時刻・料金・年齢・電話・URL・主催等が出典つきで取れること。全角数字・表記ゆれ |
| 曜日照合 | 一致／不一致／曜日表記なし／年の省略 |
| 確認ゲート | 必須項目が未確認なら確定不可、確認済み・該当なしなら確定可 |
| HP生成 | 種別ごとの表示・非表示、状態表示（文字あり）、更新履歴、time要素、見出し階層、情報なしの表示、エスケープ |
| SNS生成 | 9投稿、媒体ごとに構成が異なる、Xの文字数、情報不足メッセージ、禁止表現なし |
| AAA対応チェック | すべての fixture で自動検査がエラー0 |
| fixture | ①通常クラシック ②複数出演 ③0歳から ④ワークショップ ⑤複数回 ⑥無料 ⑦参加者募集 ⑧オープンデー ⑨完売 ⑩受付終了 ⑪出演者変更 |

fixture は架空のイベントです。実在の公演情報を使っていません。

## 9. 要検証事項（参考サイトとの突き合わせ）

- 現行HPの見出し名・項目の並び順（「公演概要」「出演」「曲目」「チケット」等の実際の文言）
- 販売状況の実際の表記（「予定枚数終了」等）と、完売後にページをどう更新しているか
- チケット取扱（窓口・電話・WEB・プレイガイド）の実際の名称と受付時間の書き方
- オープンデー等の複合イベントのページ構成
- 共催イベントでの問い合わせ先の書き方
- 施設名・室名（ホール、ギャラリー等）の正式表記 → `js/core/schema.js` の `VENUE_ROOMS` は抽出の手がかりとしてのみ使い、確認済みにはしません
